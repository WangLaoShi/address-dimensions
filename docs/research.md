# 中文地址解析项目调研

## 结论

首版适合自建轻量的地址栏解析器，采用**可更新的区划数据、按父链保留多个候选、遇到冲突显式返回状态**。两款上游都有可借鉴的实现，但直接包装其 DataFrame 返回值会继承默认猜测、旧区划或错误截断等问题。批量解析优先输出字典，便于写入 Excel 和 CSV，核心可只依赖 Python 标准库。

## 两个项目的特点与不足

| | cpca | addressparser |
| --- | --- | --- |
| 核对范围 | PyPI 0.5.5；源码提交 `9bdfd6e` | PyPI 0.2.4；源码提交 `b998dbb` |
| 匹配方法 | Aho–Corasick 找词，依据 adcode 上级关系选择，遇到县级结束一条记录 | 默认滑窗全文扫描，可启用 jieba；省市区映射与补全 |
| 输出与实用功能 | DataFrame、区划代码、命中起点、自定义重名优先级、长文本入口 | DataFrame、区划名称、详情、自定义映射、绘图；数据说明指向 2021 年统计区划 |
| 可复用思路 | 区划代码、位置证据、候选的父链约束 | 较新的部分地名、默认可不切词、保留详情的若干案例 |
| 限制 | 默认取第一个重名候选；同词条覆盖和按结束位置取匹配会丢候选；旧 adcode、虚拟分组误命中；pandas 和 C 扩展依赖 | 分别取省市区会拼出矛盾结果；按默认映射处理同名会给单一答案；pandas、jieba；干净安装后实际缺少 six |
| 维护边界 | 项目历史上的 `cut`、`open_warning` 例子不适用于当前接口 | 作者在 [#5](https://github.com/shibing624/addressparser/issues/5) 说明 fork 独立演进，不定期合并上游 |

源码入口：[cpca 匹配器](https://github.com/DQinYuan/chinese_province_city_area_mapper/blob/9bdfd6e8694b44ca3de0730bd9122c6df5916133/cpca/matcher.py)、[cpca 解析与数据加载](https://github.com/DQinYuan/chinese_province_city_area_mapper/blob/9bdfd6e8694b44ca3de0730bd9122c6df5916133/cpca/__init__.py)、[addressparser 解析](https://github.com/shibing624/addressparser/blob/b998dbbbd731098fd0f2db2558f2c39971aee37d/addressparser/__init__.py)。

在 macOS、Python 3.12 上安装两款 PyPI 包，使用默认参数解析 21 条地址栏输入，并执行 3 次 cpca 全文调用。为复测补装了 `six` 和仍提供 `pkg_resources` 的 setuptools。以下是问题驱动样例，不能据此估算总体准确率。完整的关联结论见[逐条审查](issue-review.md)。

## 建议实现

1. **数据先行。** 从国家地名信息库发布的区划代码制作可追溯快照，记录来源、发布日期、版本和校验和。使用显式的 `code`、`parent_code`、`level`，支持直辖市、市直管镇和省直管县。另建带生效区间的历史名称表，功能区、常用简称和 POI 各有独立来源。民政部规则明确规定了全国年度发布和省级乡级半年发布，适合作为更新节奏依据。[行政区划代码管理办法](https://www.moj.gov.cn/pub/sfbgw/flfggz/flfggzbmgz/202512/t20251204_528920.html)
2. **匹配保留证据。** 地址栏先做保守的空格与全半角规范化并保留原文位置。用前缀树枚举命中，保留同名、重叠和不同层级的候选，再用显式全称、出现位置及可达父链挑选。路、街、园区、建筑等详情开始后限制回扫；判断不了的简称留待消歧。显式上级矛盾返回冲突。先测准确性和吞吐，再决定是否需要可选 AC 加速。
3. **返回适合表格的结果。** 建议字段为 `province`、`city`、`district`、`township`、`adcode`、`detail`、`status`、`data_version`。完整结果附 `candidates`、`matches` 供复核，Excel 版可展开成候选数量和候选代码文本。区划代码保留字符串。状态明确区分 `matched`、`partial`、`ambiguous`、`conflict`、`unmatched`。
4. **按能力分步验证。** 先做省、市、县和详情保护，以本次复测为回归起点，再加入独立的真实样本，按明确地址、同名、道路误判、短地址分层统计误归属率和拒识率。下一阶段加入乡镇、历史区划、自定义数据与全文多地址抽取。村级、功能区、单位名称和经纬度按需求接独立数据或服务。

## 替代方案与适用范围

- **直接使用 cpca 或 addressparser。** 可快速对照现有地址表，适合允许人工核验的批量任务；需主动处理重名和旧区划。两者都可作为回归对照。
- **离线自建匹配。** 适合 Excel 分析、隐私敏感和可重复的批处理。主要维护成本是区划快照、简称和历史数据。社区五级数据可用于原型或交叉核对，版本须单独标注。[五级区划项目](https://github.com/modood/Administrative-divisions-of-China) · [历史区划数据项目](https://github.com/dataxiv/data-district)
- **POI 或地理编码服务。** 适合街路门牌、楼宇、商场、跨省校区和坐标查询。若部署时启用，需要单独核对数据覆盖、调用费用和地址传输要求。行政区代表点与地址实测坐标分别输出。

本阶段未修改上游仓库。图片型 Issue 未逐张验证附件内容。复测验证的是列出的用例，首版解析器和正式区划数据仍需实现。
